# Настройки в окружении, а не в репозитории проекта

Облачная сессия поднимает свежий контейнер: всё, что не лежит в репозитории,
теряется между чатами. Отсюда два способа, и они не взаимозаменяемы.

## 1. В репозиторий проекта — работает гарантированно

```bash
git clone --depth 1 https://github.com/021-lab/setup-coder /tmp/setup-coder
/tmp/setup-coder/setup-coder.sh /путь/к/проекту
```

`CLAUDE.md` и `.claude/skills/` коммитятся в проект и приезжают вместе с его
клоном в любом чате. Настраивать нечего. Минус — копия в каждом проекте, и
обновление правил требует повторного прогона скрипта.

## 2. В окружение — одно место на все проекты

Нужно, когда правила должны действовать и там, где репозитория проекта нет.

Меню облачного окружения в шапке сессии → **Edit** → **Setup script**:

```bash
git clone --depth 1 https://github.com/021-lab/setup-coder /tmp/setup-coder
mkdir -p "$HOME/.claude/skills"
cp /tmp/setup-coder/CLAUDE.md "$HOME/.claude/CLAUDE.md"
cp -R /tmp/setup-coder/skills/. "$HOME/.claude/skills/" 2>/dev/null || true
```

Скрипт привязан к окружению, а не к чату: все чаты этого окружения получат
настройки, для другого окружения те же строки вписываются ещё раз.

Репозиторий публичный, поэтому клонирование идёт без ключей. Если его когда-то
сделают приватным, понадобится токен на чтение в секретах окружения и адрес
вида `https://x-access-token:$TOKEN@github.com/021-lab/setup-coder`.

**Не проверено:** переживает ли запись в `$HOME` старт самой сессии —
контейнер кешируется после выполнения скрипта. Если в новом чате `CLAUDE.md`
окажется пустым, значит не переживает, и остаётся способ 1.
