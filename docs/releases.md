# Версии

Окружения клонируют не `main`, а тег. Это значит, что правка в `main` не уезжает
во все окружения сразу: она уезжает тогда, когда вы передвинете тег.

Так сделано нарочно. Setup script выполняет код из этого репозитория при каждом
старте контейнера — с `main` любая недоделанная правка немедленно оказалась бы
во всех новых чатах, включая те, где вы в этот момент работаете над чем-то
другим.

## Текущий тег

`v1` — это то, что ставят окружения.

```bash
git clone --depth 1 --branch v1 https://github.com/021-lab/setup-coder "$TMP/src"
```

## Как выпустить изменение

```bash
# 1. Правка в main, с проверкой обоих режимов на временных каталогах
./setup-coder.sh --repo /tmp/проба --check
./setup-coder.sh --env --check

# 2. Коммит в main
git add -A && git commit -m "…" && git push

# 3. Передвинуть тег на новый коммит
git tag -f v1
git push -f origin v1
```

После этого настройки получит **следующий** контейнер каждого окружения. Текущие
чаты продолжают работать с тем, что у них уже установлено, — перезапуск не
требуется, но и обновления в них не будет.

## Когда завести v2 вместо передвижения v1

`v1` двигается, пока изменения совместимы: добавилось правило, добавился скилл,
поправилась формулировка. Если изменение ломает то, что от репозитория ожидают
— переименован режим установщика, изменился формат `mcp.json`, правила
переписаны так, что старое поведение агента исчезло — завести `v2` и перевести
окружения на него по одному. Тогда откат это одна строка в настройках
окружения, а не разбор, что именно поменялось.

## Проверить, что стоит в окружении

```bash
cat ~/.claude/.setup-coder
```

Там версия и дата установки. Если файла нет — Setup script не доработал: скорее
всего не прошёл `git clone`, и причина в логе старта контейнера.
