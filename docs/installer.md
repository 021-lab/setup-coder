# setup-coder.sh

Один скрипт, два режима. Разница только в том, куда ставится и как ложатся
правила; состав — правила, скиллы, MCP-серверы — одинаков.

```
setup-coder.sh --env             в $HOME/.claude
setup-coder.sh --repo [КАТАЛОГ]  в репозиторий проекта, по умолчанию текущий
setup-coder.sh --help            короткая справка
любой режим + --check            показать, что изменится, и ничего не писать
```

## Что куда ложится

| Источник | `--env` | `--repo` |
| --- | --- | --- |
| `CLAUDE.md` | `$HOME/.claude/CLAUDE.md`, файл целиком | `CLAUDE.md` проекта, блоком между маркерами |
| `skills/*/` | `$HOME/.claude/skills/` | `.claude/skills/` проекта |
| `mcp.json` | `claude mcp add --scope user` | слияние в `.mcp.json` проекта |
| — | `$HOME/.claude/.setup-coder`: версия и дата установки | — |

Почему правила ложатся по-разному: в `$HOME` файл наш целиком, спорить не с чем.
В репозитории проекта рядом живут правила самого проекта, поэтому общие
вставляются блоком между `setup-coder: начало` и `setup-coder: конец` — повторный
запуск меняет только блок, остальное не трогает.

## Правила, которым подчиняется установка

- **Повторный запуск безопасен.** Что совпадает — не переписывается. Уже
  настроенный MCP-сервер не считается ошибкой: `claude mcp add` возвращает на
  него `1` и текст `already exists`, и установщик разбирает именно текст.
- **Скилл заменяется каталогом целиком.** Пофайловое копирование оставило бы на
  месте установки файл, который в источнике удалили. Скиллы, которых в источнике
  нет, не трогаются совсем.
- **`.mcp.json` сливается.** Наши серверы добавляются и перекрывают одноимённые,
  чужие серверы и прочие поля файла сохраняются. Если файл проекта — не
  корректный JSON, слияние отменяется с ошибкой, а не портит файл.
- **Отметка содержит только версию, без времени.** Со временем файл менялся бы
  при каждом запуске, и в проекте появлялся бы пустой диff. Когда ставили —
  записано отдельно, в `$HOME/.claude/.setup-coder`.

## Чего установщик не делает

- **Не ставит плагины Claude Code.** Superpowers ставится командой
  `/plugin install`; плагины живут в конфигурации Claude Code, файлом их не
  положить.
- **Не кладёт ключи.** Ни ключей, ни токенов в репозитории нет и быть не должно.
  Их место — секреты окружения; `CONTEXT7_API_KEY` сервер читает сам.
- **Не коммитит.** В режиме `--repo` изменения остаются в рабочем дереве:
  посмотреть `git status` и закоммитить — ваше решение.

## Зависимости и поведение без них

| Нужно | Для чего | Если нет |
| --- | --- | --- |
| `bash`, `awk`, `diff`, `cmp` | правила и скиллы | установка невозможна |
| `python3` или `python` | разбор и слияние `mcp.json` | MCP пропускается с предупреждением, правила и скиллы ставятся |
| `claude` в `PATH` | MCP в режиме `--env` | MCP пропускается с предупреждением |
| `git` | определить версию для отметки | отметка пишется как «без версии» |

Любая нехватка — предупреждение в stderr и продолжение, а не падение: окружение
должно подняться хотя бы частично настроенным.

## Коды возврата

`0` — установка прошла или в режиме `--check` ничего не записано.
`1` — отказ с сообщением: неизвестный ключ, нет такого каталога, `--env` с
каталогом, целевой каталог совпадает с источником.
